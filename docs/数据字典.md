## 6. 标准化排位分查找表 (`standardized_scores.json`)

- **路径**: `processed/standardized_scores.json`
- **大小**: 2.86 MB (2,998,793 bytes)
- **类型**: JSON Object，2 个顶层 key
- **记录数**: 12,579 条

### 顶层结构

```json
{
  "meta": { ... },
  "data": [ 12579 条记录 ]
}
```

### meta 字段

| 字段 | 类型 | 示例 | 说明 |
|:----|:----|:-----|:-----|
| `description` | string | `河南高考标准化排位分查找表` | 说明 |
| `formula` | string | `standardized = ln(N/rank) / ln(N) × 1,000,000` | 公式 |
| `total_records` | number | `12579` | 记录总数 |

### data 字段

| 字段 | 类型 | 示例 | 说明 |
|:----|:----|:-----|:-----|
| `year` | number | `2025` | 年份 |
| `category` | string | `history` / `physics` | 科类 |
| `score` | number | `686` | 原始分数 |
| `count` | number | `12` | 该分人数 |
| `cumulative` | number | `12` | 累计人数 |
| `high_rank` | number | `1` | 最高排位 |
| `low_rank` | number | `12` | 最低排位 |
| `high_std` | number | `1000000` | 最高标准化分 |
| `low_std` | number | `805439` | 最低标准化分 |

### 标准化分公式

```
standardized = ln(总人数 / 排位) / ln(总人数) × 1,000,000
```

**标准化分范围**: 0 ~ 1,000,000。满分对应排名第1，0分对应排名最末。

### 用途

核心转换表。将分数→排位→标准化分，解决跨年份分数不可比的问题。推荐系统中的 `high_std` / `low_std` 统一使用此标准化分体系，使得不同年份的录取数据可以直接比较。

## 附录 A: 标准化分体系

### 为什么需要标准化分？

不同年份的高考难度不同，考生人数不同（如 2017 年文科 23.4 万 vs 2025 年历史类 35.2 万），导致同一排位在不同年份的含义不同。标准化分将每年每个科类的排位映射到统一尺度 `[0, 1000000]`，实现跨年份可比。

### 公式

```
standardized = ln(N / rank) / ln(N) × 1,000,000
```

其中 N = 该年度该科类考生总数。

### 特点

- **满分 (1,000,000)**: 全省第 1 名
- **0 分**: 全省最后 1 名
- **非线性映射**: 排位越靠前，标准化分区间越密集（符合高考分数实际分布）

### 使用字段

所有 `processed/` 下的文件均使用 `high_std` 和 `low_std` 字段表示标准化分区间，推荐系统据此判断"冲稳保"。
