# 高考志愿推荐系统 - 需求记录

> 记录时间：2026-05-27
> 记录人：小螃蟹 🦀

---

## 一、登录 / 账户系统

- **位置**：与分数查询放在同一页面，不做独立登录页
- **注册方式**：用户名 + 密码直接注册，流程简单
- **用途**：为志愿表填写做准备，每个账户管理自己的志愿表数据

## 二、志愿表 - 核心功能 ⭐

- **一个账户** 最多可创建 **50 个学生**的志愿表
- **河南高考志愿规则**（2025 年起新高考 3+1+2）：
  - 普通类：**64 个志愿**
  - 艺术/体育类：**48 个志愿**
- **核心能力**：每个学生独立填写、保存、管理各自的志愿表
- **志愿表内容**：每个志愿包含 → 学校 + 专业组 + 6个专业 + 排序
- **辅助功能**：志愿表应能结合查询结果（冲稳保推荐）来辅助填报

## 三、志愿填报规则（2025 河南新高考）⭐

### 3.1 志愿单位：院校专业组

❌ **不是** 填学校（如"郑州大学"）
❌ **也不是** 填专业（如"郑州大学临床医学（第一附属医院）"）
✅ **而是** 填 **院校 + 专业组**（如"郑州大学-物理类-101组"）

64 个志愿，每个都是 **一个院校专业组**。

### 3.2 每个志愿内部的规则

每个志愿（院校专业组）内部可以选 **最多 6 个专业**，分两种情况：

| 情况 | 说明 |
|------|------|
| **专业组内专业少（≤6 个）** | 选完组内所有专业 = 志愿完成，无需纠结 |
| **专业组内专业多（如上百个）** | 用户必须从大量专业中 **挑出 6 个** 填入，才算完成一个志愿 |

> 📌 典型例子：郑州大学物理类 104 组包含几十上百个专业，用户需要从中选 6 个——这正是系统的核心价值所在。

### 3.3 数据需求

- 需要导入 **2025 年招生计划** 数据，提取：
  - 每个学校下的 **专业组** 列表
  - 每个专业组包含的 **全部专业**
- 志愿填报界面需清晰展示：学校 → 专业组 → 可选专业列表

### 3.4 系统核心价值

> **这是本系统与往年高考填报工具最大的不同，也是考生和家长最为迷惑的地方。**
> 系统要辅助考生理解和操作"院校专业组"填报模式，帮他们：
> 1. 知道每个专业组里有哪些专业
> 2. 从大量专业中筛选出想报的 6 个
> 3. 64 个志愿有序排列、不重复、不遗漏

### 4.4 对系统的设计要求

**大专业组（>6个专业）** → 展示全部专业列表，用户需从中**挑选最多6个**填入，系统需提供搜索/筛选辅助

> 📌 再小的组也可能只有1个专业（多达1,601组），选组即选专业，操作极简
> 📌 再大的组可能有58个专业，系统需帮用户快速定位想报的6个

## 五、核心推荐算法 ⭐

### 5.1 核心思路

> 将不同年份、不同分数的位次，统一标准化为一个可比数值（0~100万），通过比较考生与学校/专业的标准化排位分段来确定录取概率。

### 5.2 算法步骤

#### 第一步：计算考生的标准化排位区间

⚠️ **关键：考生一个分数对应的是一个位次区间，不是单个点！**

河南高考分数段 100~700 分仅 600 档，但考生约 100 万人。集中分段每分有几千人同分。

根据一分一段表，对于考生分数 score：
- **同分人数** = count[score]
- **累计人数** = cumulative[score]（该分数的最低排名，即最差排名）
- **最高位次** = cumulative[score] - count[score] + 1（同分中最好排名）
- **最低位次** = cumulative[score]（同分中最差排名）

→ 考生位次区间 = **[最高位次, 最低位次]**

**用区间两端分别计算标准化排位分：**
- 原始比例：`ratio = (N - rank) / N`（N=全省总人数），值域 (0, 1]
- 用 **ln 变换** 标准化：对 ratio 做对数变换处理，将集中分段的位次差异合理映射
- 最终标准化到 0~1 后乘以 **1,000,000**，得到标准化排位分

→ 考生标准化排位区间 = **[最低排位分, 最高排位分]**

```
标准化排位分范围: 0 ~ 1,000,000
高分 → 数值大    低分 → 数值小

示例：
河南 2024 年理科，总考生 N = 560,000
560 分：同分 2,300 人，最高位次 50,001，最低位次 52,300
  → 最高排位分 ≈ (560000-50001)/560000 = 0.9107 → 910,700
  → 最低排位分 ≈ (560000-52300)/560000 = 0.9066 → 906,600
  → 考生区间 = [906,600, 910,700]
```

#### 第二步：计算学校/专业的标准化排位分段

根据历年录取数据（录取统计），提取每个学校/专业：
- **最高录取位次** = 录取学生中排名最好的（门槛最高）→ 标准化 → 最高排位分
- **最低录取位次** = 录取学生中排名最差的（门槛最低）→ 标准化 → 最低排位分

得到每个学校/专业的 **标准化排位分段**：`[最低排位分, 最高排位分]`

> 💡 学校与专业分开计算：
> - **专业级**：该专业各年份录取分数的标准化区间
> - **学校级**：该校所有专业录取分数的标准化区间并集
> - **专业组级**（2025 新高考需要）：该专业组的各个专业的标准化区间

#### 第三步：考生与学校/专业对比 → 冲稳保判定

**双方都是区间，对比两个区间的重合度：**

```
学生标准化区间 = [S_low, S_high]
学校/专业区间 = [T_low, T_high]
    (T_low是该专业最低录取分的标准化低位，T_high是最高录取分的标准化高位)

重合度计算：
  overlap = max(0, min(S_high, T_high) - max(S_low, T_low))
  学生段宽 = S_high - S_low
  学校段宽 = T_high - T_low
  重合比例 = overlap / max(学生段宽, 学校段宽)

判定逻辑（看重合区域的位置）：
  整个区间重合 → ✅ 稳（重合比例高，学生正好在学校范围内）
  学生区间高过学校区间 → 🔽 保（学生位次整体优于学校历年生源）
  学生区间低于学校区间 → 🔼 冲（学生位次整体低于学校历年生源）
  完全不重合且差距大 → ❌ 不可能 或 💸 浪费分数
```

> 重合度越高越稳，学生段偏上为保，偏下为冲。
> margin 可根据分段动态调整（高分段 margin 小，低分段 margin 大）

### 5.3 2025 新高考适配

- 2024 及以前是院校录取（文/理科），有直接的历年录取数据
- 2025 是新高考专业组模式，暂无录取数据
- 方案：将 **2025 招生计划中的专业组** 与 **历年该校该专业的录取标准化排位分** 关联
  - 专业组的标准化区间 = 组内各专业历年标准化区间的并集
  - 这样虽不完全准确，但已是最佳近似

### 5.4 概率判定（基于区间重合）

```
学生区间 = [S_low, S_high]    学校区间 = [T_low, T_high]
重叠量 = max(0, min(S_high, T_high) - max(S_low, T_low))

判定：
  学生段整体低于学校段（S_high < T_low）          → 🔼 冲
  学生段整体高于学校段（S_low > T_high）          → 🔽 保
  两段有重叠（overlap > 0）                       → ✅ 稳
  两段差距过大（无重叠且差距远大于正常margin）     → ❌ 不可能/浪费
```

| 判定 | 说明 |
|------|------|
| 🔼 冲 | 重合偏下段，学生有机会但需要运气 |
| ✅ 稳 | 区间有重合，属正常录取范围 |
| 🔽 保 | 重合偏上段，稳妥但不能保证专业 |
| ❌ 不可能 | 学生段远低于学校段下限 |
| 💸 浪费 | 学生段远高于学校段上限 |

## 六、实施计划

### 第一阶段：数据预处理（优先做）

1. **导入并解析 2025 招生计划** → 提取院校专业组结构
2. **计算各年份标准化排位分**
   - 读取一分一段表，计算每个分数对应的标准化排位分
   - 为历年录取数据（学校、专业）计算标准化排位分段
   - 生成标准化排位分查找表（JSON）
3. **2025 专业组与历年数据关联**
   - 将 2025 年的专业组，映射到历年该校的录取数据
   - 计算每个专业组的预估标准化排位分段

### 第二阶段：API + 前端开发

1. 搭建 FastAPI 后端（封装标准化查询、冲稳保推荐）
2. 开发前端页面（分数查询 + 登录注册 + 志愿表管理）

### 第三阶段：志愿表功能

1. 学生管理（单个账户管理最多 50 个学生）
2. 志愿表编辑器（64 个志愿 × 专业组 × 6 个专业）
3. 冲稳保推荐 + 一键填入志愿表
